# 让用户的 AI 沙箱替 ChatCut 出片（设计提案 · DRAFT）

导出、AI 自检截帧、转写这三类计算，从 ChatCut 的云挪到用户 agent 自带的沙箱（Cowork / Claude Code / Codex）；原始素材放用户自己的 Google Drive。ChatCut 只发"菜谱"、记账。原型已在 2 核沙箱跑通：2 分钟 1080p 成片 142 秒。

> 写于加入 ChatCut 之前，基于公开资料（[ChatCut-Inc/agent-plugin](https://github.com/ChatCut-Inc/agent-plugin)、chatcut.io/docs）。标注"待核实"的都是推断。

## 1. 谁做什么

| 工作 | 放哪 | 理由 |
|---|---|---|
| 导出成片 | 用户沙箱 | ffmpeg 合成主画面 + 浏览器只渲动效层 |
| AI 自检截帧（今天走云端 `preview_timeline`） | 用户沙箱 | 同一套合成逻辑截单帧，0.06–0.45 s |
| 转写 | 用户沙箱 | whisper base 12× 实时，small 4.5× |
| 代理文件、缩略图、波形 | 用户沙箱 | ffmpeg 秒级 |
| 原片、成片长期存储 | 用户 Drive | 沙箱会被回收，只当缓存 |
| 项目数据、协作同步、导出记录 | ChatCut 服务器 | 体量小，编辑器实时同步离不开 |
| AI 生成（视频、配音、音乐） | 第三方 GPU | CPU 跑不动，不在范围内 |
| 没有 agent、在编辑器点导出的用户 | 用户浏览器 | WebCodecs 编码；都不行才走付费云端 |

## 2. 一次导出怎么走

```
ChatCut MCP                      用户沙箱 (ccrender)                  用户 Drive
① report_render_capabilities ◄── 有沙箱 / 核数 / ffmpeg / Chromium
② get_render_bundle ──────────►  渲染包：时间线快照 + 素材地址
                                  + 短期 Drive token（仅此项目）
                                  ◄─────────────────────────────────── 拉原片
                                 ③ 渲染：动效 → 透明 PNG 帧（共用 1 个浏览器）
                                         画面 → ffmpeg 每 10 秒一段 · 混音 · 合并
                                         每步落盘，超时重跑即续（exit 75）
                                 ④ 分块续传上传 ─────────────────────► 成片
⑤ register_export ◄────────────  export-manifest.json（哈希 · 渲染器版本 · 耗时）
```

① ② ⑤ 是需要在 ChatCut MCP 新增的三个工具，类型见 [`contract/types.ts`](../contract/types.ts)。今天的 `submit_export` 保留，作为没有沙箱时的兜底。

## 3. 渲染器的四个关键决定

1. **混合渲染。** 剪切、多轨、字幕、混音用 ffmpeg（1080p 合成约 0.68× 片长）；只有动效层走浏览器。全部走浏览器逐帧截图会慢 5–6 倍。
2. **动效输出 PNG 帧，不编码成视频。** 实测慢的是 ProRes 4444 编码，不是启动浏览器。改成 PNG 序列 + 共用浏览器后，每帧 0.153 s → 0.045 s。
3. **分段 + 断点续跑。** 每 10 秒一段，每步写 `state.json`。断点按"渲染包哈希 + 渲染器代码哈希"作废，改了代码不会拼进旧结果。
4. **导出必须和编辑器一致。** `mg/index.jsx` 是替身；落地时换成编辑器正在用的 web 渲染器，并在渲染包里钉住版本。

## 4. 实测（Cowork 沙箱，2 核 / 7.8 GB，合成素材）

| 任务 | 耗时 | 备注 |
|---|---|---|
| 30 秒 1080p，2 个动效 | 41 s | 自动检查 5 项全过 |
| 2 分钟 1080p，6 个动效 | 142 s | 合成 82 · 动效 31 · 混音预览 27 |
| 单帧自检 | 0.06–0.45 s | 与成片同一时刻 PSNR 37 dB |
| 转写 24 秒人声 | 1.9 / 5.2 s | whisper base / small |
| 每次只给 15 秒预算 | 2 次调用 | 从断点继续 |

真人素材解码更重，需要再测。

## 5. 风险

| 风险 | 对策 |
|---|---|
| 算力小：2 核，4K / 长片跑不动 | 按时长和分辨率设上限，超出转浏览器编码或云端 |
| 沙箱被回收、单次调用有时限 | 分段 + 断点续跑（已验证） |
| 成片可信度：用户机器出的文件 | 导出记录带 sha256、渲染包哈希、渲染器代码哈希 |
| token 泄露 | Drive 用 `drive.file` 最小权限、短有效期、仅限当前项目 |
| 轮询消耗用户对话额度 | 后台跑，低频查询 |
| 渲染授权 | 若底层用 Remotion，确认公司授权是否覆盖用户设备上渲染 |

## 6. 待核实

3. 用户里 Cowork / Claude Code / Codex 各占多少，决定沙箱路径能覆盖多大比例。
4. 用正式 Google OAuth 应用跑通 Drive 拉取和上传（原型里写了未测）。
